# 《AI 课堂 · 系列课子 CUI》板块 ③ 作业闭环 · 详细产品方案

> 版本：v1.1（产品方案，无技术实现 / 仅用于评审）
> 更新摘要（v1.0 → v1.1，5/13 评审拍板）：
> 1. **作业阶段与课次状态强绑**：`stage` 必须与课次实时 `educationStage` 一致，禁止老师事后补派；
> 2. **个性化作业回退到 3 档分层 A/B/C**：沿用四板块 PRD § 6.3 `layeredVersions`，不做"每人一套"以控成本；
> 3. **答案 toggle 取消，改为三方流转模型**：学生只看题目 → 学生点「一键批改」即时对答案 → 答案+解析发给**家长**作为辅导材料 → 提交与批改结果同步老师确认。**反作弊红线从"家长不看题/答案"调整为"学生提交前不看答案、家长只在派发后拿到材料用于陪练"**。
> 4. § 11 验收路径同步刷新到 v1.1 流程。
>
> 起草背景：5/13 用户带 7 张截图（作业列表 → 创建作业 → 知识点弹窗 → AI 生成 → 发布 → 已发布回看 → 预览）讨论新需求；本文承接《AI 课堂 · 系列课子 CUI》四大板块 PRD §6 做**详细化下钻**，不替换四板块总览。
> 适用入口：**场景二（加入一个教育机构）** · 单课子 CUI · 履约卡 → `📝 作业` 图标 → 系列课子 CUI
> 关联组件参考：`LessonOperationListCard`（卡外列表卡占位摘要）、`AiClassroomSideConversationPanel`、`eduCoursesPersistence`、`eduImBus`、`aiClassroomSkillRegistry`（`tc-question` / `ta-asgmt` / `sa-asgmt` / `sa-mistakes` / `ta-variant`）
> 范围守卫：本方案**默认仅作用于场景二**（`scenario=edu-one` / `isScenarioTwo` 守卫）；其他场景的作业入口若复用，需在该方案对应小节单独点名，否则不被本期改动。

### 1.1 与"风采点评/履约管理/资料"板块的边界

- **风采点评（① 板块）**：作业里学员的"高光时刻 / 进步证据"可作为AI 生成个性化点评的输入之一（作业表现回流），但**不**反向：风采点评不写回作业 store。
- **履约管理（② 板块）**：请假学员**自动跳过**作业派发（默认）；老师可勾选"请假学员也派发（在家自学）"。
- **资料（④ 板块）**：发布作业生成的 PDF 自动挂到该课次资料库（教师视角"我上传"标签），学生侧只能看到"作业 PDF"而看不到其他备课素材。

#### 字段规则

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| 课程名称 / 科目 / 年级 | 自动 | 从 `lessonKey` → `course` 派生，**只读** | 防止老师手改与课次不一致 |
| 学生列表 | 是 | 整班 active 学员（请假者置灰可勾） | 支持子集（个性化作业 / 补课场景） |
| 作业阶段 | 是 | **强绑** `educationStage` | 见下方"阶段强绑规则"；老师**不可手改** |
| 题目难度 | 是 | `medium`；阶段切换时给建议（pre=简单 / in=中等 / post=中等或困难） | 仅当 mode=统一 时一档；个性化模式下按 A/B/C 三档分层 |
| 作业模式 | 是 | `统一作业` | 见下方"作业模式 · 个性化 A/B/C 三档" |
| 知识点 | 是 | 空，必须选 | 三入口：① 大纲勾选 ② AI 解析附件 ③ 手动输入 |
| 题型 + 数量 | 是（≥ 1 组） | 单选题 × 5 | 单组上限 20 题；多组总数上限 30 题（防 AI 生成超时） |

#### 作业阶段强绑规则（v1.1 拍板）

| 课次实时状态 | 强制 `stage` | 表单内行为 |
|---|---|---|
| `pending` / `soon`（课前） | `pre` | 阶段字段**置灰不可改**，显示"课前 · 由课次状态自动锁定" |
| `in`（上课中） | `in` | 同上，显示"课中 · 由课次状态自动锁定" |
| `completed`（课后） | `post` | 同上，显示"课后 · 由课次状态自动锁定" |

设计意图：
- **禁止老师手动选阶段**，避免"今天周一上完了周二的课，又派周一的课前作业"这种语义混乱；
- **如果老师确实有"上完课了再补派课前小测"的需求**：建议在四板块 PRD 后续版本提供"系列内跨课次派发"能力（指定派到下节课的 pre 阶段），而不是允许在当前课次乱选阶段；
- 阶段 chip 文案保留 hint，但是不可选状态：

| 阶段 | 提示语（仅展示） |
|---|---|
| 课前 | 课前用于唤起前置概念，建议中等难度 |
| 课中 | 课中建议中等难度，配合互动答题更有效 |
| 课后 | 课后可提升难度用于巩固训练 |

#### 作业模式 · 个性化 A/B/C 三档（v1.1 拍板）

选中"个性化作业"后：

- AI 按学情画像将学员自动分配到 **A 拔高 / B 巩固 / C 补强** 3 档；
- 每档生成**一套独立题目**（共 3 套 × N 题），而非每位学员一套（控制 AI 算力）；
- 表单下方出现**分组预览**：
  ```
  ┌─ A 拔高（4 人） · 难度 偏难 ─────────────┐  ← AI 自动归档，老师可拖学员到其他档
  │ [李小明] [王伟] [张楠] [刘一菲]          │
  └──────────────────────────────────────┘
  ┌─ B 巩固（18 人） · 难度 中等 ─────────────┐
  │ [...]                                    │
  └──────────────────────────────────────┘
  ┌─ C 补强（8 人） · 难度 偏易 ─────────────┐
  │ [陈可] [赵欣宇] [...]                    │
  └──────────────────────────────────────┘
  ```
- 老师可在分组预览里**拖学员调档**（避免 AI 错分）；
- 生成时 3 套题在 `HomeworkPreviewCard` 内**三 Tab 切换**，老师可逐档审；
- 数据模型字段：`layeredVersions: { A: Question[], B: Question[], C: Question[] }`（沿用四板块 PRD § 6.3）；
- 若学情画像数据不足（如新班 / 试听课），AI 默认全员入 B 档，老师手动调；
- 注：本期**不**做"30 人 × 30 套题"的全个性化（算力 / 延时成本太高），后续版本承接。

#### 校验

- 学生数 ≥ 1
- 知识点 ≥ 1
- 题型总数 ≥ 1，≤ 30
- 截止时间（隐藏字段，默认 = 阶段对应缺省值）：
  - 课前：当节开课前 1 小时
  - 课中：当节下课时
  - 课后：当节下课后 24 小时（可在发布前手改）

```
│ ▢ 口语与表达                                          │
```

要点：
- 二级树形结构（一级 = 课程领域 / 二级 = 具体知识点）；
- 三种知识点录入方式之一：
  - **大纲勾选**：从教学大纲（`eduCoursesPersistence.lessons[].kpTree`，需新增字段；本期 demo 用 mock 数据）拉知识点树
  - **AI 解析附件**：老师上传 PDF/Word，AI 抽取知识点候选 → 显示同样弹窗但**已预勾选**
  - **手动输入**：弹一行 input，老师自定义知识点名（直接入 `knowledgePointSource: "manual"`，不绑定大纲 ID）
- 选中后回填到表单"知识点"区，以 chip 形式显示，可单独 ✕ 删除

#### 交互细节

| 操作 | 说明 |
|---|---|
| `♻` 单题重生 | 用同一知识点 + 题型重新生成；不影响其他题 |
| `🗑` 单题删除 | 立即删除并重排序；最少保留 1 题（删到 0 题时按钮置灰） |
| `⊕ 添加题目` | 弹窗 2 选 1：① 让 AI 再补 N 题（指定知识点 / 题型） ② 手动录题（表单：题面 / 选项 / 答案 / 解析） |
| `查看答案与解析` | 默认折叠；展开后可行内编辑（textarea）；预览卡上**仅老师/管理者本人**可见，标"*仅你 / 家长可见" |
| `题目来源` | "AI 出题" / "手动录入" / "AI 出题 · 老师编辑" 三态 |
| `发布作业` | 二次确认弹窗："将作业派发给 N 位学员（题目）+ N 位家长（题目+答案+解析），发布后可在 24h 内撤回。"；点确认 → 走 `publishHomework()` |

#### 派发分流（v1.1 拍板的核心模型）

发布动作触发**三方分流**，**没有**任何 toggle 可调（避免老师误发答案给学生）：

| 收件方 | 收到的内容 | IM preset |
|---|---|---|
| **学生** | 仅题面（题目 + 选项；无答案、无解析） | `homeworkAssignedToStudent` |
| **家长** | 完整辅导包：题面 + 答案 + 解析 + AI"今晚怎么陪练"建议 | `homeworkAssignedToParent` |
| **老师**（自己） | 已发布回执 + 进度看板入口 | 本端确认，无外发 IM |

#### 数据模型字段调整（vs v1.0）

- 删除 `showAnswersToStudent: boolean`（不再有 toggle）；
- 新增 `dispatchPolicy: "split"` 标识当前固定策略（保留扩展位，未来如出现"只发题目不发答案给家长"的低龄场景，可加 `dispatchPolicy: "questions-only"`）；
- 答案 / 解析在 `LessonHomework.questions[].correctAnswer / analysis` 内**始终保留完整数据**，由消费方按角色 ACL 决定可见性（学生端打码，家长 / 老师端完整呈现）。

#### 反作弊红线（v1.1 调整说明）

- **v1.0 红线**：家长不看题面 / 答案（怕家长给孩子答案）；
- **v1.1 红线**：学生在**点「一键批改」前**看不到答案；家长可看题目+答案+解析作为辅导材料。
- 调整理由（产品权衡）：
  - v1.0 的"家长完全屏蔽"在实践中过严：低年级家长本就承担陪练责任，反而把陪练能力关掉；
  - v1.1 把红线收紧到"学生作答过程中"：只要学生作答时本端看不到答案，"先做后批改"的学习闭环就成立；
  - 家长拿到答案的语义是"陪练参考资料"，不是"代写工具"；配合下方 § 7.3 异常检测（家长指纹答案直接灌进学生端会被识别），抵消了潜在的代写风险。

#### "✨ 一键生成作业"重点击

- 第一次点击：AI 后台异步生成（约 8-15s，含 loading 状态）；
- 已有内容时再次点击：弹"将丢弃当前 N 题草稿并重新生成，确定？"二次确认；
- 单题 `♻` 是局部重生，不弹确认；
- 整体生成失败兜底：「AI 出题超时，可重试 / 改用手动录入」。

  - 老师侧自动跳回 `CreateHomeworkFormCard`，表单字段从撤回的作业回填（便于改 toggle / 增删题后重发）；

#### 反馈页关键点

- **"一键批改"前后的答案可见性切换**：
  - 批改前：答案 / 解析对学生完全隐藏；
  - 批改后：解析 / 正确答案对该学生**永久解锁**（再次进入查看也可见）；
- **AI 三态标签**（沿用 PRD § 6.4）：
  - `系统自动批改`（客观题指纹比对 + 主观题置信度 ≥ 90%）
  - `AI 初批 · 待老师复核`（主观题置信度 70-90%）
  - `老师正在批改`（主观题置信度 < 70% / 检测异常）
- `重做错题`：错题自动入"我的错题本"，重做不影响本次成绩；
- `申诉错判`：单题级，弹"我认为我的答案是对的，因为..." → push `homeworkAppealToTeacher` IM；申诉期老师在 `HomeworkGradingCard` 端审核。

#### 老师对接（同步链路）

学生点 `一键批改` → 提交并自动批改 → **同步触发 3 件事**：
1. 学生侧反馈页就地刷新（即时）；
2. 老师 `HomeworkGradingCard` 的 Tab2 待复核数 +1（如有 AI 低置信度题或异常）/ 已批数 +1（如全客观题正常）；
3. IM `homeworkSubmittedToTeacher` 推老师（红点）+ `homeworkSubmittedToParent` 推家长（"孩子已交 · 得分 8/10"）。

### 4.3 错题本回灌

- 提交后错题进"我的错题本"（沿用 Skill 卡 `sa-mistakes`）；
- 错题本累计 ≥ 3 道时主对话顶部出现"♻ 错题挑战"chip；
- 老师在 `ta-mistakes` Skill 卡看到聚类后的高频错点，可一键"导入下节课开场 5 分钟"。

#### 设计意图重申

- **不再屏蔽家长的"陪练材料"**：v1.0 的反作弊红线在实操中过严，家长承担了大量陪练责任却拿不到辅导资料；
- **改用"账户级隔离"+"过程隔离"防代写**：
  - 家长账户访问的是 `HomeworkParentViewCard`，**没有**入口能"切换到孩子身份做作业"；
  - 学生端答题界面**没有**任何答案/解析提示，物理上无法直接抄；
  - 异常检测（§ 7.3）发现"答案指纹与家长侧辅导材料雷同"会触发"疑似抄答"标记。

### 6.1 主模型 `LessonHomework`

```ts
interface LessonHomework {
  /* —— 标识 —— */
  id: string                                          // "hw-${shortHash}"
  refNo: number                                       // 12314 等编号；机构粒度递增；老师 / 学生 / 申诉链路引用
  seriesId: string
  outlineIndex: number
  lessonKey: string

  /* —— 基础元数据 —— */
  title: string                                       // "0513 补课：123146666666作业"，可改
  courseName: string                                  // 自动派生（只读）
  subject: string                                     // 自动派生（只读）
  grade: string                                       // 自动派生（只读）
  teacherId: string
  teacherName: string

  /* —— 派发配置 —— */
  stage: "pre" | "in" | "post"                        // **强绑课次实时状态，老师不可改**
  difficulty: "easy" | "medium" | "hard"
  mode: "uniform" | "personalized-abc"                // 个性化 = A/B/C 三档分层（非全个性化）
  targetStudentIds: string[]                          // 派发学员（默认整班 active）
  excludeLeaveStudents?: boolean                      // 默认 true：请假学员不派

  knowledgePoints: {
    id?: string                                       // 大纲 ID（若来自大纲）
    label: string
    source: "outline" | "ai-parse" | "manual"
  }[]
  
  questionTypeConfig: {
    type: "single" | "multi" | "judge" | "short-answer" | "essay"
    count: number
  }[]

  /* —— 题目 ——
   *   mode = "uniform"          → questions 字段存全班题
   *   mode = "personalized-abc" → layeredVersions 三档独立题；questions 留空
   *   一份作业仅二选一，不并存
   */
  questions?: HomeworkQuestion[]                      // 统一模式
  layeredVersions?: {                                 // 三档分层模式
    A_advanced: { questions: HomeworkQuestion[]; studentIds: string[] }
    B_consolidate: { questions: HomeworkQuestion[]; studentIds: string[] }
    C_remedial: { questions: HomeworkQuestion[]; studentIds: string[] }
  }
  HomeworkQuestion: {
    id: string
    type: HomeworkQuestionType
    prompt: string
    options?: string[]                                // 选择题用
    correctAnswer: string | string[]                  // 单选/判断/简答=string；多选=string[]
    analysis: string
    knowledgePointLabel: string
    source: "ai" | "manual" | "ai-edited"
  }

  /* —— 发布配置 —— */
  dispatchPolicy: "split"                             // v1.1 固定 = "split"：学生题面 / 家长完整辅导包
  requirementText?: string                            // 作业要求（默认有，可改）
  pdfAttachmentId?: string                            // 发布后生成；同时写入 eduCoursesPersistence.lessons[].materialFiles
  parentMaterialPdfId?: string                        // 家长侧"题目+答案+解析"打水印的辅导版 PDF
  deadlineAt: number                                  // ms
  publishedAt?: number
  withdrawnAt?: number

  /* —— 提交 & 批改 —— */
  submissions: HomeworkSubmission[]
  HomeworkSubmission: {
    studentId: string
    studentName: string
    layer?: "A" | "B" | "C"                           // 个性化模式记录该生归属
    answers: Record<string, string | string[]>       // questionId → answer
    submittedAt: number                               // = 学生点"一键批改"的时间
    
    /* 自动批改结果（客观题指纹比对，主观题 AI 评分） */
    autoReview?: {
      score: number                                   // 0-100
      perQuestion: Record<string, {
        correct: boolean
        confidence: number                            // 0-1；客观题 = 1.0
        comment?: string
      }>
      overallConfidence: number                       // 三档判定用（仅含主观题）
      suspectAnomaly?: "fast-submit" | "answer-similar" | "matches-parent-material"
      batchedAt: number
    }
    
    teacherFinal?: {
      score: number
      perQuestion?: Record<string, { correct: boolean }>
      comment?: string
      attachments?: WeDiskFile[]                      // 讲解视频等
      confirmedAt: number
    }
    
    appeal?: {
      questionId?: string                             // 单题级 or 整份
      reason: string
      submittedAt: number
      resolvedAt?: number
      resolution?: "upheld" | "rejected"
    }
    
    extensionRequest?: {
      reason: string
      requestedAt: number
      approvedAt?: number
      newDeadlineAt?: number
    }
  }
}
```

## 7. AI 出题 + AI 批改

### 7.1 AI 出题

| 输入 | 用途 |
|---|---|
| 知识点 | 出题主轴；个性化模式下与该生学情画像交叉 |
| 题型 + 数量 | 题目结构 |
| 难度 | 在题目复杂度 / 干扰项设置 / 计算量上做调档 |
| 学情画像（仅个性化模式）| 给每位学员定难度档（A 拔高 / B 巩固 / C 补强） |
| 上传附件（如果用了 AI 解析附件）| 题目素材来源限定（避免出大纲外题） |
| 历史错题（仅个性化模式）| 优先出该生历史错题相关变式 |

- 触发 = `✨ 一键生成作业` 按钮；
- 不预生成、不轮询；
- 后台异步 8-15s 生成（demo 用 mock 数据 + 1.5s 延时）；
- 重生粒度三档：整体重生（清空草稿）/ 单题重生（不影响其他）/ 补 N 题（追加）。

### 7.2 自动批改 + 置信度三档（v1.1 调整）

| 题型 | 自动批改方式 | 置信度 |
|---|---|---|
| 单选题 / 多选题 / 判断题 | **答案指纹比对**，秒级出对错 | 固定 = 1.0 |
| 短答（标准答案型）| 答案指纹比对（容忍大小写 / 全半角） | 固定 = 0.95 |
| 简答 / 论述（主观题）| AI 评分 | 0-1，按 § 6.4 三档 |

主观题置信度三档（沿用 PRD § 6.4，名称统一）：

| 置信度 | 行为 | 学生侧标签 |
|---|---|---|
| ≥ 90% | 直接出分 | "系统自动批改" |
| 70-90% | 进老师"待复核"队列，24h 必看 | "AI 初批 · 待老师复核" |
| < 70% / 检测异常 | 强制人工 | "老师正在批改" |

学生点 `一键批改` 时：
1. 客观题指纹比对 → 立即出对错；
2. 主观题 AI 评分 → 95% 在 5 秒内完成（demo mock 用 1.5s 延时）；
3. 整份得分 = 客观题 + 主观题（按比重）；
4. 整份置信度 = 主观题部分的最低置信度（决定老师是否复核）。

### 7.3 异常检测（v1.1 新增"家长辅导材料雷同"）

| 信号 | 行为 |
|---|---|
| 提交时间 < 30 秒 | 标 `fast-submit`；进老师人工 |
| 答案与同班 ≥ 2 人指纹相似度 ≥ 90% | 标 `answer-similar`；进老师人工 |
| 同一题反复提交 ≥ 3 次 | 标 `repeated-submit`；进老师人工 |
| **答案与家长侧辅导材料正解逐字相同（短答 / 论述题）**| 标 `matches-parent-material`；进老师人工；防"家长把答案直接念给孩子抄" |
| 老师人工核完异常 → 学生无合理申诉 → 记入"学习行为标签"（仅老师可看，**不**公开给家长，防对抗） | |

> `matches-parent-material` 检测原理：把家长侧 PDF 内 `correctAnswer / analysis` 的关键 n-gram 与该生作答 n-gram 比对；客观题不参与该检测（答案就一个字母，必然相同）。

## 10. 异常态清单（v1.1）

| 异常 | 行为 |
|---|---|
| 老师 AI 生成超时（> 30s, 2 次 retry 失败） | toast"AI 出题超时，可重试 / 改用手动录入"；不卡在 loading |

| 老师 24h 内撤回作业但学生已交 | 学生侧标"作业已撤回"，原提交保留备查；不再展示给学生；家长侧 PDF 失效 |
| 老师误发给错学员（target 勾错） | 24h 内撤回 → 重发 |
| 同班 ≥ 3 名家长申诉作业难度 | 老师侧 `HomeworkGradingCard` 顶部出现"⚠ 班级 N 位家长反馈难度"折叠条；不强制改 |
| AI 批改抽样：老师改分率 > 30% 持续 1 周 | 系统给老师"AI 批改 prompt 治理建议"（机构后台），不直接公开 |
| 个性化作业 A/B/C 分档时学情数据不足 | 全员入 B 档；表单顶部黄色提示"⚠ 本班学情数据不足，已统一入 B 档，可手动调" |
| 个性化作业生成失败回退 | 自动降级到"统一作业 · 中等"+ 老师 IM"已为你回退到统一作业，可手动改题" |
| 家长把 PDF 答案给孩子直接抄 | § 7.3 `matches-parent-material` 检测命中 → 老师 IM 私密提示 → 老师可决定是否提醒家长（不自动通知，避免误伤） |
| 家长试图截图分发作业 PDF | PDF 自带"机构 + 学员姓名"水印；多机构同孩子时水印按当前家长账户对应学员显示 |
| 多账户家长（爸+妈）同时打开辅导卡 | 不冲突；不同设备独立访问，操作以最后一次为准 |
| 老师"撤回作业"后未在 60 分钟内重发 | 学生侧标"作业取消"，IM 同步家长 |
| 课次被调课（系列段 / 单节） | 已发布作业**沿用原课次**挂；老师如需迁移到新课次，需手动"重发到新课次"（避免数据漂移；与四板块 PRD § 9.4 横切一致） |
| 学生 / 家长收到作业 IM 但作业已撤回 | IM 卡上挂"⚠ 此作业已被老师撤回"红条 |
| 学生作答时切换到另一份未做作业 | 当前作业自动存草稿；切回时无缝继续 |
| 全班一键批改时主观题 AI 服务异常 | 客观题正常出分；主观题部分标"AI 批改中，老师稍后会复核"；不阻断学生看客观题结果 |

## 11. 验收路径（Demo · 场景二 · v1.1）

1. **老师 · 完整布置流（课后阶段）**
   - 课次状态 = `completed`（已完课）；履约卡 → 📝 作业 → 子 CUI push `HomeworkListCard`（Tab1 空状态）
   - 点底部 `⊕ 布置作业` → `CreateHomeworkFormCard`
   - 学生列表默认全员；保留勾选 林小安 1 人
   - 阶段字段**自动锁定 = 课后**（灰态，点击给提示）
   - 难度 = 中等；模式 = 统一作业
   - 知识点 → 大纲勾选弹窗 → 勾 听力与观看 / 阅读与观看
   - 题型 = 单选题 × 5
   - 点 `✨ 一键生成作业` → 8-15s 后 `HomeworkPreviewCard` 展示 5 题
   - 验证：答案 / 解析区域标"*仅你 / 家长可见"
   - 单题 `♻ 重生`第 3 题 → 题目刷新
   - **不再有**"答案 toggle"
   - 点 `发布作业` → 二次确认弹窗显示"派发给 1 位学员（题目）+ 1 位家长（题目+答案+解析）"
   - 确认 → 弹 `HomeworkPublishedCard`「发布成功」
2. **学生 · 答题 + 一键批改**
   - 履约卡 → 📝 → `HomeworkStudentListCard` 看到该作业 · 待做
   - 点 `开始做` → `HomeworkDoCard` 一题一卡作答
   - **验证：作答过程中没有任何答案 / 解析提示**
   - 卡住 → 点 `问提问帮手` → 走 `sa-copilot` Skill 卡思路引导（仅思路，不给答案）
   - 答完 10 题 → 底部 `✓ 一键批改` 高亮 → 点
   - 客观题秒级出对错；主观题 AI 评分 ~1.5s
   - 反馈页：总分 8 / 10，错的第 3、7 题展开**才**看到正解+解析
   - 错题 2 道入错题本
3. **家长 · 全程辅导**
   - 履约卡 → 📝 → `HomeworkParentViewCard`
   - 主对话收到 `homeworkAssignedToParent` IM 后即可看完整辅导材料：题目 + 答案 + 解析 + AI 陪练建议
   - 验证：PDF 自带"机构 + 林小安"水印
   - `加入家庭日历` → 19:30 提醒
   - 孩子做完后 → 家长侧"孩子已交 · 总分 8/10 · 错点摘要：第 3、7 题"
   - **验证：家长看不到孩子第 3 题具体选了什么**
4. **老师 · 批改 + 确认**
   - 履约卡 → 📝 → Tab2 「批改作业 (1)」
   - `HomeworkGradingCard` 顶部 1/1 已交（自动批 + 待老师确认）
   - 选林小安 → 看 AI 批改记录 → 点 `✏ 改分` → 改 8 → 9
   - `💬 反馈` → 附讲解视频 → 提交
5. **学生 · 收老师终评**
   - 主对话收到 `homeworkConfirmedToStudent` IM
   - 学生侧反馈页"系统自动批改" → "老师已复核"，分数 8 → 9
6. **家长 · 收老师终评**
   - 主对话收到 `homeworkConfirmedToParent` IM
   - 家长侧反馈页显示"老师已复核 · 终评 9"
7. **异常 · 学生申诉**
   - 反馈页 `⚠ 申诉错判` → 写理由
   - 老师 IM 红点；进 `HomeworkGradingCard` 申诉队列 → 接受
   - 学生分数 9 → 10；IM 通知
8. **异常 · 家长辅导材料雷同检测**
   - 让学生在简答题里**逐字粘贴**家长侧 PDF 的解析作为答案
   - 老师 `HomeworkGradingCard` 待复核区出现⚠"林小安作答与家长辅导材料雷同"
   - 老师可选"私下提醒家长 / 教育孩子独立思考 / 维持原判"
9. **异常 · 学生延期**
   - 截止前 1 小时未交 → 学生侧弹 `申请延期 24h`
   - 老师 IM 待审批 → 同意 → 学生侧截止时间 +24h；家长 IM 同步
10. **个性化作业 A/B/C 三档**
    - 老师切到 `个性化作业` → 表单出现 A/B/C 分组预览（AI 自动归档）
    - 老师拖一位学员从 B 档到 A 档
    - 点 `✨ 一键生成作业` → 三 Tab 切换看三套题
    - 发布 → 每位学员收到自己档位的题面，家长收到自家孩子档位的辅导材料

## 12. 关键术语（v1.1）

| 术语 | 含义 |
|---|---|
| 作业 / `LessonHomework` | 一节课派发的一份作业实体；多份作业属于同课次 |
| 作业编号 / `refNo` | 机构粒度递增数字，UI 显示在卡片元信息行（"📦 12314"） |
| 作业阶段 / `stage` | `pre` / `in` / `post`，**强绑** `educationStage`，老师不可手改 |
| 派发学员 / `targetStudentIds` | 该作业的真实派发对象，可不等于整班；默认整班 active 学员 |
| 作业模式 / `mode` | `uniform`（统一作业）或 `personalized-abc`（个性化作业 A/B/C 三档分层） |
| 派发策略 / `dispatchPolicy` | v1.1 固定 = `split`：学生收题面，家长收完整辅导包 |
| 一键批改 | 学生作答完毕点击后，系统对比标准答案 + AI 评分主观题，即时反馈对错并同步老师 |
| 系统自动批改 / AI 初批 / 老师已复核 | 学生侧标签三态；客观题 = 系统自动；主观题置信度高 = 系统自动；置信度中 = AI 初批；老师改分 / 确认后 = 老师已复核 |
| 错题本 / 错题本回灌 | 学生侧累积错题集合（沿用 `sa-mistakes` Skill）；老师可在 `ta-mistakes` 看聚类后导入下节备课 |
| 学生侧作业 PDF | 仅含题目；离线兜底用 |
| 家长侧辅导 PDF / `parentMaterialPdfId` | 完整题目 + 答案 + 解析；带"机构 + 学员名"水印 |
| 个性化作业 A/B/C 三档 | AI 按学情把学员分到 A 拔高 / B 巩固 / C 补强 3 档；每档独立一套题；老师可拖学员调档 |
| `matches-parent-material` | 异常检测信号：学生作答与家长辅导材料雷同；防"家长把答案直接给孩子抄" |

## 13. 待沟通 / 后续（v1.1）

1. **课中作业 vs 现有 `tc-question` Skill 卡**：本方案让"课中作业"也走 `CreateHomeworkFormCard`，与 `tc-question` 的"即时随堂题"是否重叠？建议：`tc-question` 保留"老师在课中口播一题让全班 30 秒抢答"的快速场景；本方案的"课中作业"则是结构化、有答题记录、能进错题本的更重的形态。运营要确认两条路线的话术 / 引导。
2. **作业模板**：老师高频复用同一套配置（学科 + 难度 + 题型）。是否需要"保存为模板"+"从模板创建"？建议本期不做，看老师使用频次再加。
3. **知识点大纲数据源**：本方案依赖 `eduCoursesPersistence.lessons[].kpTree`（新增字段）；需明确数据填充链路（机构后台 / 教研运营导入）。本期 demo 用 mock 静态数据。
4. **PDF 生成**：发布作业时自动生成**两份** PDF（学生侧仅题 / 家长侧含答案+解析+水印），涉及前端 PDF 渲染（jsPDF / html2pdf 等）。本期 demo 用 mock URL + 写死 1.34MB 占位；真实接入需确定服务端 / 前端方案。
5. **跨课次派发"补课前作业"**：v1.1 把 `stage` 与课次状态强绑后，"上完今天的课才想起来要派今晚作业的课前小测"场景被禁用。需考虑后续版本提供"系列内跨课次派发"能力（指定目标课次 + 该课次的 stage），不要在当前课次内允许乱选 stage。
6. **作业题库 vs AI 出题**：是否允许机构对接第三方题库（如智学网）？本期默认 AI 出题，第三方题库由后续版本承接。
7. **家长侧反作弊红线调整影响**：v1.0 → v1.1 把"家长完全屏蔽"放宽到"家长拿到完整辅导材料 + 异常检测 + 账户隔离"。
   - 法务 / 隐私团队需确认：家长侧拿到完整答案 / 解析的合规边界（是否需要在机构入会协议里增加条款）；
   - 教研团队需确认："让家长看答案"是否影响低龄段学习习惯（小学 1-3 年级或可保留"家长辅导按需开启"）；
   - 若反馈不佳，可加机构后台 / 老师粒度的"家长侧 ACL 开关"，把 `dispatchPolicy: "questions-only"` 作为兜底选项。
8. **管理者（场景 9）介入深度**：本方案聚焦场景二 = 教师 / 学生 / 家长；管理者侧的"作业达成率看板 / 异常审计 / 老师 prompt 治理建议"留到《主CUI交互》主对话的看板卡承接，由场景 9 PRD 单独描述。
9. **多孩子家庭**：家长账户绑定多个孩子（兄弟姐妹同机构 / 跨班）时，`HomeworkParentViewCard` 是否要做"按孩子切换"？建议本期沿用现有"履约卡 → 选课程 → 进子 CUI → 看本课程对应孩子"，不在作业卡内新增切换器。
10. **教学大纲缺失时的 fallback**：若 `kpTree` 为空（机构未导入大纲），知识点录入是否强制走 AI 解析附件或手动输入？本期建议自动隐藏"大纲勾选"按钮，避免空状态。

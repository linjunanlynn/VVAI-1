## 0. 文档说明

用户原始需求中列出 **评价风采 / 签到-请假-调课 / 作业 / 备课-资料** 共 4 类能力，并以"三大板块"为统称。本 PRD 按职能解耦，**实际拆为 4 个产品板块**输出（保持每块边界自洽，便于跨角色对齐与排期）；如需对外宣讲口径仍以"三大板块"统称：

- 板块 ①「**风采点评**」（素材累积 + AI 一键生成总结/点评/归属 + 教师审核 + 家长接收闭环）
- 板块 ②「**履约管理**」（签到 / 请假 / 调课，三者同源 attendance 模型）
- 板块 ③「**作业闭环**」（课中随堂练 + 课后个性化作业 + AI 批改）
- 板块 ④「**备课与资料**」（教学大纲解析 + 散落资料归类 + 师生统一查看）

## 1. 背景与目标

### 1.1 背景

当前「课程履约」卡片在场景 6/7/8 内已可点击进入"系列课子 CUI"，子 CUI 主要由 18 张 Skill 卡 + 教师控制条 + 课次抽屉 + ChatSender 构成，承载了课前/课中/课后的对话型能力。但围绕"履约"这一业务对象，4 类高频能力还散落在以下问题里：

| 现状问题 | 表现 |
|---|---|
| 风采点评无端到端闭环 | 教师课中只能拍照存档；课后报告卡（`TeacherLessonReportReviewCard`）虽含一键群发家长，但风采素材 / 课堂总结 / 个性化点评尚未串成"老师课中累积素材 → 一键 AI 生成 → 教师审定 → 家长收风采报告 feed"的标准链路；同时履约卡上"风采"+"点评"两图标对老师产生认知分裂 |
| 签到/请假/调课操作分散 | 履约卡 11 个图标里 `签到 / 请假` 各占一格，且每个 action 当前都路由到系列子 CUI（占位）；学生/家长/教师的差异化流程未明确 |
| 作业链路缺乏个性化 | 现有 Skill 卡 `tc-question`（随堂题）、`ta-asgmt`（AI 初批）、`sa-asgmt`（学生作业）相互独立，缺乏"课中错点 → 课后作业 → AI 批改 → 错题本回灌"完整链路 |
| 备课与资料缺乏机构尺度组织 | `eduCoursesPersistence` 已支持"教学大纲上传 → 1.5s mock 解析 → 自动建课次目录"，但散落资料的"AI 自动归档到对应课次"尚未呈现；学生侧未开放只读资料视图 |

### 1.2 设计目标

1. **以"系列课"为最小完整单元**：所有 4 类能力都在系列课子 CUI 内闭环，避免跨页跳转。
2. **角色差异化但模型同源**：同一份 attendance / review / homework / material 数据，不同角色看到不同视图与不同 CTA，禁止重复维护。
3. **AI 提效但人工有最终裁量**：所有"AI 生成"内容（评价文案、个性化作业、归档结果）默认**草稿态**，需教师 / 学生 / 家长在 1 步内确认或撤销。
4. **不重复造轮子**：复用现有《组织状态》、《主CUI交互》、`eduCoursesPersistence`、`eduImBus`、`aiClassroomLessonSeriesPersistence` 持久层与 IM 推送通道。
5. **谨慎的功能边界**：管理者（场景 9）不进入单课子 CUI（项目守卫已明确），但需在"履约总览/审批"层有反向看见入口（在板块 ② 中体现）。

### 1.3 非目标（本期不做）

- 视频会议端 / 直播 SDK 改造（仍由现有线上互动教室承担）
- 督导抽课、巡课等 admin 视角进入单课的能力
- 真实人脸识别建模（本期 AI 生成"个性化点评"以**学情画像 + 课中行为标签**作为输入；人脸采集/识别仅作为"哪些孩子出现在这段视频"的辅助标签，**不**做声纹 / 表情情绪算法）
- 续费 / 财务 / 课时核销（已由"课程商品 / 订单管理"覆盖）
- 跨机构数据打通

## 3. 信息架构总览

### 3.1 进入子 CUI 后的"承接锚点"

每个图标点击后，进入系列课子 CUI 都应**自动定位到当前 active outline**（`decideInitialActiveOutlineIndex`）并在该 outline 的 thread 内以 AI 气泡形式 push 一张对应能力卡，复用既有 marker 机制（`buildSeriesRescheduleFormContent` / `buildLessonMaterialsMarkerContent` 等）。

| 入口 | 触发的卡片 marker | 卡片粒度 |
|---|---|---|
| 资料 | `<<<RENDER_AIC_MATERIAL_CARD>>>` | **课次级** |
| 签到 | `<<<RENDER_AIC_ATTENDANCE_CARD>>>`（新增） | 课次级 |
| 请假 | `<<<RENDER_AIC_LEAVE_FORM>>>`（既有 series leave） | 课次级 |
| 调课 | `<<<RENDER_AIC_RESCHEDULE_FORM>>>`（既有 series reschedule） | 课次级 |
| 作业 | `<<<RENDER_AIC_HOMEWORK_CARD>>>`（新增） | 课次级 |
| **风采点评 / 风采报告** | `<<<RENDER_AIC_REVIEW_*>>>` 同族 3 子型（新增）：<br>· `_ASSETS`（A 素材列表：教师 pre/in/post-未发；学生家长 post-未发 = 空状态）<br>· `_REPORTS`（B 课后报告草稿：教师 post-点过 AI 生成）<br>· `_PUBLISHED`（C 已发布回看：教师 post-发过；学生家长 post-收到后） | 课次级 + 学员级 |
| 备课 | `<<<RENDER_AIC_PREP_CARD>>>`（新增） | 课次级（教师专属） |

> 卡片由 `AiClassroomSideConversationPanel` 在当前 outline thread 内由系统消息**自动选型 push**，老师 / 学生 / 家长在任何时刻打开"风采点评"入口，AI 会按 **stage × 角色 × 发布状态** 三维路由到正确子型，无须用户选择。

### 3.2 与现有体系的边界

- **不替换** 18 张 Skill 卡：4 大板块的卡片承担"履约对象"维度的强结构化交互；Skill 卡承担"对话/能力"维度的灵感与提效。两者可共存（用户在卡片上点"下一步"chip 仍可触达 Skill）。
- **不替换** 课次抽屉：系列内课次切换、调课/请假入口仍走现有 outline drawer。新增的「签到 / 作业 / 风采 / 点评 / 备课」入口走"操作条 / 11 图标"，避免抽屉过载。
- **不替换** 课件/微盘/课程商品端：所有资料相关数据仍以 `eduCoursesPersistence` 为单一事实源；新卡片仅是同一 store 在子 CUI 内的"课次切片视图"。

### 3.3 子 CUI 顶部"履约徽章"统一升级

在已有 Header（VVAI Logo · "AI课堂" · X）下方的"系列名 · 第 N/M 节"那一行，**右侧新增 4 个微徽**（仅展示态，不可点；点击直接 push 对应能力卡到当前 thread）：

```
[系列名 · 第 5/12 节]    ✅ 30/32  📝 22/32  📷 已发 28/30   📚 12 项
                          签到      作业      风采点评       资料
```

颜色规则：达成 ≥ 90% 绿；70-90% 灰；< 70% 黄；未生成内容 不展示徽章（避免空状态噪音）。

风采点评徽章按教育阶段差异：
- 课前 / 课中：显示「📷 素材 N 项」（仅老师可见；学生 / 家长不出现该徽章，避免引起"是不是已经有结果"误解）；
- 课后未点 AI 生成：显示「📷 待生成 N 素材」（仅老师可见）；
- 课后已生成草稿未发：显示「📷 草稿 N/M」（仅老师可见）；
- 课后已发布：显示「📷 已发 N/M」（老师 + 学生 + 家长可见）。

## 4. 板块 ① 风采点评

> v1.1（本节按 5/11 评审拍板重写）：
> - 履约卡 "风采" + "点评" 合并为单一文字入口「**风采点评**」（无 icon）；
> - 老师侧统称「风采点评」（动作向）；学生 / 家长侧统称「**风采报告**」（结果向）；
> - 取消原 5 步线性 wizard，改为「**素材态 ↔ 报告态**」双视图 + 一次 AI 转换按钮；
> - AI 归属、班级总结、个性化点评全部下放为**后台异步任务**，老师不再被强迫做"AI 该做的事"。

### 4.1 业务定义

「风采点评」（老师侧）/「风采报告」（学生家长侧）是同一份数据的两面：

- **风采素材** = 课中孩子的照片 / 视频原始片段（老师拍摄 / 上传，**过程态**）
- **课堂总结** = AI 课后基于教学内容自动生成的本节课重难点与亮点（班级粒度，**1 条**）
- **个性化点评** = AI 课后基于该生课中互动与学情数据生成的"**一句话**"评语（学员粒度，**N 条**）
- **课后报告** = 给到单个家长的最终产物 = 该生的素材切片 + 班级课堂总结 + 该生一句话点评

整条主链路：

```
课中: 老师持续累积素材   ─────────────────────────────────┐
                                                          │
课后: 老师点 [✨ AI 生成个性化点评风采]                    │
        ↓                                                  │
      AI 后台异步：                                        │
      ① 人脸识别 → 素材自动归属到孩子                      │
      ② 综合教学内容 → 生成 1 条班级课堂总结              ←┘
      ③ 综合课中互动 + 学情数据 → 每孩子 1 句话个性化点评
        ↓
      老师看到「每个孩子的课后报告草稿卡列表」N 张
        ↓
      老师可：筛选 / 改文字 / 改素材 / 单发 / 一键全发
        ↓
      已发送的家长在《主CUI交互》主对话收到 IM feed
        ↓
      家长点开 → 看自家孩子的「风采报告」（素材 + 总结 + 一句点评）
```

### 4.2 数据模型

```
LessonReview {
  seriesId, outlineIndex, lessonKey

  /* —— A 素材态：老师课前/课中持续累积 —— */
  assets: Asset[]
  Asset {
    id, kind: "photo" | "video", thumbUrl, mediaUrl,
    capturedAt, uploaderTeacherId,
    /** AI 后台异步填充；老师不直接操作 */
    aiBindStatus: "pending" | "boundToStudent" | "groupShot" | "unmatched",
    boundStudentIds?: string[],            // 命中 1 人 = 个人切片；命中 ≥2 人 = 班级共同片段
    aiConfidence?: number,                 // 0-1
    blurredFaceCount?: number              // 智能糊脸数（隐私统计）
  }

  /* —— B 报告态：老师点 AI 生成后产出 —— */
  reportGenerated: boolean
  generationTask?: {
    startedAt, finishedAt, retried, status: "running"|"ready"|"failed"
  }

  classSummary?: {                          // 班级粒度，1 条
    teaching: string,                       // "本节以 Zoo 为主题，教学目标聚焦动物英文单词 + 简单描述句型 ..."
    keyPoints: string[],                    // 本节重难点 3-5 条
    editedByTeacher?: boolean
  }

  studentReports[N]?: {                     // 学员粒度，N 条
    studentId, name, avatar
    boundAssetIds: string[],                // 该生的素材切片（含 AI 自动 + 老师手动追加）
    aiReviewSentence: string,               // AI 生成的一句话个性化点评（来源：互动数据 + 学情）
    teacherEdited?: {                       // 老师最终稿（继承 AI 句 + 任意编辑）
      sentence, editedAt
    },
    sendStatus: "draft" | "sent" | "withdrawn" | "skipped",
    sentAt?, withdrawnAt?,
    parentReadAt?, parentLikedAt?,
    tags?: string[]                         // ["亮点", "进步", "需关注"] 用于筛选
  }

  /* —— C 已发布回看：状态聚合 —— */
  publishedCount, draftCount, withdrawnCount
}
```

> 与现有 `aiClassroomLessonSeriesPersistence` 兼容：本模型新增一份 `LessonReview` 持久化 key，不破坏既有 `SeriesRescheduleRecord` / `SeriesLeaveRecord`。

### 4.3 三视图（A / B / C） + AI 转换按钮

老师侧入口 = 「风采点评」（履约卡文字按钮）→ 系列课子 CUI 内 push 一张 `<<<RENDER_AIC_REVIEW_*>>>` 大卡。系统按 **stage × 发布状态** 自动路由子型：

| 当前状态 | 路由到 | 主功能 |
|---|---|---|
| stage = `pre` 或 `in` | **A 素材列表** | 拍 / 传 / 删 |
| stage = `post` 且 `reportGenerated = false` | **A 素材列表 + AI 生成 CTA** | 续传 + 一键生成 |
| stage = `post` 且草稿就位（`reportGenerated = true`，任意 draft 未发） | **B 课后报告草稿** | 改 / 单发 / 全发 |
| stage = `post` 且全部 `sent` | **C 已发布回看** | 撤回 / 重发 / 补发 |

学生 / 家长侧只可能落到「空状态」或「C 视图」（详见 §4.5）。

关键交互：

- **课堂总结** 顶部 1 张（班级粒度），**家长侧每张孩子报告里都会带上此总结**（家长能顺便了解班级整体教学内容）；

- **学员卡纵向列表**（不是横向 tab）：默认 2 列响应式，老师 1 屏可见 4-6 张，按学情 tag 自动分组排序（亮点 → 进步 → 中段 → 需关注）；
- **一句话点评强约束**：AI 默认输出**单句**（< 80 字），过长截断；老师改写时也以"建议保持一句"为提示文案，避免家长侧阅读疲劳；
- **重生粒度**：班级总结 1 个按钮、单生句 1 个按钮、全部回炉 1 个按钮，**三档独立**；
- **"需关注"标签学员**：AI 一律采用"亮点 + 1 个具体改进"句式（避免伤害性表达）；AI 拦截到不合规措辞会在卡上提示「AI 已柔化"今天不专注" → "本节有几次走神，建议下次坐前排"」；
- **删除素材**：老师在 B 视图也可点缩略图删除，删除后该学员卡自动重布局；
- **草稿强制审核**：未点"发送"前，家长侧完全看不见；只要点了"发送"，对应学员卡顶部出现「✅ 已发 12:34」徽。

### 4.4 AI 生成与隐私规则

#### AI 输入与触发

| 来源 | 用途 |
|---|---|
| 课中影像（视频/照片） | 素材主体；线下增强复用 `oc-tt-camera` 已识别的发言者切片 |
| 学情画像 (`tt-portrait`) | 个性化点评的"亮点 / 进步 / 需关注"分组 |
| 课堂行为时间轴 (`pa-detail`) | 一句话点评的"具体场景" |
| 随堂题表现 (`tc-question` / `sa-mistakes`) | 一句话点评的"客观依据" |
| 教学大纲 + 课件 | 班级课堂总结的"教学内容/重难点" |
| 人脸识别（仅本期） | 仅做素材 → 学生归属的**框选辅助**，**不**做情绪/表情识别 |

#### AI 触发时机

- **触发** = 老师在 stage = post 点「✨ AI 生成个性化点评风采」按钮（**唯一显式入口**）；
- 不预生成、不轮询——避免下课瞬间老师还想补素材却被"AI 已生成"绑死；
- 老师点了 → 后台异步约 30s 完成（中位）；
- 可重生：班级总结 / 单生句 / 全部回炉三档（次数不限，每次重生写入审计）。

#### 隐私三条强约束

1. **班级共同片段对全班家长可见，但智能糊脸保护非相关学员**：
   - "命中 ≥ 2 人" 的素材被 AI 标记为 `groupShot`，默认作为班级共同片段附在**每张**学员报告里；
   - 非该家长授权可见的孩子人脸**自动模糊**（系统在生成端实现，老师无需选择）；
   - 卡上显示「已自动模糊 N 人 · 仅展示已授权人脸」提示。
2. **个人切片仅对该家长可见**：
   - "命中 1 人" 的素材属 `boundToStudent`，仅该生家长能看到；
   - 即便其他家长授权了自己孩子也**不能**看别家孩子的个人切片。
3. **家长撤销授权实时生效**：
   - ≤ 5 分钟内之前已发的对应素材在家长端置灰 + 标"已撤回展示"；
   - 后续不再为该生生成切片（与 §9.4 横切约定一致）。

### 4.5 学生 / 家长视角

#### 4.5.1 学生（场景 7）

履约卡点「风采点评」→ 子 CUI push `<<<RENDER_AIC_REVIEW_PUBLISHED>>>`（学生子型）：

| 状态 | 呈现 |
|---|---|
| **课前 / 课中 / 课后未发布** | **空状态卡**：「📷 风采报告还没生成<br>老师会在本节课结束后整理并发送给你，发送时会提醒你查看。」<br>不展示任何素材、任何按钮 |
| **课后已发布 + 该生本节有报告** | 单生视图：班级课堂总结 + 我的素材切片 + 老师一句点评 + 「👍 已读 / 转发到我自己的微微 AI 主对话置顶」 |
| **课后已发布但该生被老师 skip** | 「📷 本节没有你的报告（老师未发送）」+ 引导"看本周累计风采" |

学生**绝不**看到同班同学的个人切片或老师审核中心。

#### 4.5.2 家长（场景 8）

履约卡点「风采点评」→ 子 CUI push `<<<RENDER_AIC_REVIEW_PUBLISHED>>>`（家长子型）：

学生 / 家长在 stage = pre / in / post-未发布 三种时机看到的空状态都使用**同一文案模板**（教育阶段 + 角色微调）：

| 角色 | 阶段 | 文案 |
|---|---|---|
| 学生 | pre / in | 📷 风采报告还没生成<br>老师会在本节课结束后整理并发送给你，发送时会提醒你查看。 |
| 学生 | post-未发 | 📷 老师正在为本节课整理风采报告<br>整理完成后会发给你，请稍候——我们会在主对话提醒你。 |
| 家长 | pre / in | 📷 孩子的风采报告还没生成<br>老师会在本节课结束后整理并发送给你，发送时我们会在主对话提醒你查看。 |
| 家长 | post-未发 | 📷 老师正在为本节课整理孩子的风采报告<br>整理完成后会通过主对话提醒你查看。 |

> 设计意图：把"老师拍照中、AI 算了一半、还没审核完"等中间态对学生 / 家长统一收敛为"还没好"，避免暴露老师工作流细节。

### 4.6 管理者（场景 9）— 抽样审计 + 合规观察

履约卡「风采点评」对管理者**不进单课子 CUI**，而是 push `<<<RENDER_EDU_REVIEW_DASHBOARD>>>` 到主 CUI：

- 本周已发送报告数 / 待审稿数 / 撤回数（按校区 / 老师 / 班级）；
- 抽样审核入口：随机抽 5 条已发报告，管理者「✓ 合规 / ⚠ 触发再培训」→ 转化为老师"评语合规分"；
- **强红线**：被打"伤害性表达 / 隐私泄露"标签的报告 ≥ 3 条 / 月 → 老师次月起进入「**报告二审制**」（教务复核后才发出）；
- **未发率监控**：某老师月度"已上课但未发报告"占比 > 30%，进入观察名单（不强制要求 100% 发，但要看趋势）。

### 4.7 异常与降级

| 场景 | 行为 |
|---|---|
| 课中无影像（线上无录制 / 线下摄像头故障） | A 视图素材列表为空；老师在 post 可手动上传"补拍"素材；如仍为 0，「✨ AI 生成」按钮置灰，老师可选择"仅发课堂总结 + 一句话点评（无素材）"模式 |

## 5. 板块 ② 履约管理（签到 / 请假 / 调课）

### 5.1 业务定义与同源建模

三者本质都是**一节课的 attendance 状态变更**，应共用同一份 attendance 模型，避免分裂：

```
LessonAttendance {
  seriesId, outlineIndex, studentId
  status: "expected" | "checkedIn" | "late" | "left" | "leaveApproved" | "leavePending" | "absent" | "rescheduled"
  checkedInAt?, lateMinutes?
  leaveRequest? { byRole: "student"|"parent", type, needMakeUp, reason, approvedBy?, at }
  rescheduleRequest? { fromLabel, toLabel, toScheduledAt, reason, approvedBy?, at }
  makeUpLink? { sourceOutlineIndex, targetOutlineIndex }  // 补课关系
}
```

> 现有 `aiClassroomLessonSeriesPersistence` 的 `SeriesRescheduleRecord` / `SeriesLeaveRecord` 是本模型的子集，本期改造**只扩 attendance 字段，不拆现有持久化 key**，保持兼容。

### 5.2 角色 × 场景流程

#### 5.2.1 签到

**老师视角**：履约卡点「✅ 签到」→ 子 CUI push `AttendanceCard` 显示本节实时签到表（30/32 已到、1 请假、1 待签到）。

- 课前：可看名单、未到学员一键 IM 催签（复用 `eduImBus`）；
- 课中：自动签到结果实时刷新（线上 = 进会议室即签到；线下 = 摄像头识别 + Pad 刷脸）；可"补签 / 改异常"；
- 课后：未签到学员保留 24h"补签申请"通道。

**学生视角**：默认无需手动操作。
- 课前 5 分钟出现"准备就绪 / 我已就位"按钮（不强制）；
- 异常分支：教室无网络 / 设备故障 → 学生主动"申请补签"，需上传 1 张佐证（拍照 / 老师确认截图），老师 24h 内审批。

**家长视角**：只读看孩子签到结果，**不**承担任何签到操作（避免家长替孩子刷签到）。
- 出现"未签到"超过 5 分钟会主动 push 提醒到家长（"孩子还没就位"）；

**管理者视角**：本节 / 本周 / 本月签到达成率看板，按校区 / 老师 / 班级 / 学员维度下钻；高频缺勤学员名单可一键转家访。

#### 5.2.2 请假

| 谁发起 | 对谁有效 | 必填 |
|---|---|---|
| 学生（场景 7） | 自己 | 类型 + 原因（1 句） |
| 家长（场景 8） | 自己孩子 | 类型 + 原因（1 句）+ 是否补课 |
| 老师（场景 6） | 任意学员（代请） | 类型 + 原因 + 是否补课 + 备注（教师代记原因） |

**审批策略**（默认；机构可调）：
- 课前 ≥ 24h 申请：自动通过；
- 课前 < 24h 申请：进入老师审批队列（老师不在线则进入教务兜底队列，4h 内必须有结论）；
- 课中临时请假：自动通过 + 同步老师 + 同步家长（双向通知）；
- 退课时段（课后申请）：默认拒绝；走"补签"通道。

请假成功后**自动联动**：

- 该生本节 attendance.status = "leaveApproved"；
- 课后老师点 ✨ AI 生成时，该生的"个人切片归属"自动跳过，AI 仅基于学情数据为其生成一句话点评（如老师选择"发该生"，文案会自动柔化为"本节课请假，期待下次见面"等）；
- 作业 / 资料**仍**默认推送（学生在家可学习）；
- 课时核销策略由"机构课时规则"决定（本 PRD 不深入），**默认事假不扣课时、病假不扣课时、个人事务扣课时**，可一处配置。

#### 5.2.3 调课

调课的关键是"系列粒度"vs"单节粒度"：

| 粒度 | 谁能发起 | 影响 |
|---|---|---|
| **单节调课** | 老师 / 学生（含家长代）/ 管理者 | 仅本节时间改变 |
| **系列后续整段调课** | 老师 / 管理者 | 从某一节起所有后续课次时间重排 |

> 学生 / 家长**只能**发起单节调课（避免一次申请影响全班 32 人 12 节）。系列段调课必须老师 / 管理者主导。

冲突检测（产品要求，技术不在本 PRD）：

1. 候选时段 ≠ 该班学员中任意一人已被占用的其他系列课时段（推算软冲突，可标记不阻断）；
2. 候选时段 ≠ 老师其他班级时段（强冲突，禁止保存）；
3. 候选时段 ≠ 教室时段（线下；强冲突）；
4. 候选时段 ≠ 法定节假日（软冲突，提示但允许）。

UI 推荐：调课表单卡内置"AI 建议 3 个候选时段"，每个候选都附"该候选下家长接受率预测"（基于历史调课数据，无即标"无历史"）。

### 5.3 异常与降级

| 异常 | 行为 |
|---|---|
| 双家长各自代请假，理由不一致 | 以最晚一次为准 + IM 提示前一位"已被覆盖" |
| 老师代签错人（签到错误） | 5 分钟内可"撤销签到"；> 5 分钟需教务介入 |
| 调课后该班 ≥ 3 名家长不接受 | 系统自动 IM 推该 3 家长"是否需要排补课"；不阻断调课，但记入老师"调课影响分" |
| 学生请假后又想取消 | 课前可自助取消；课中 / 课后不可取消（避免数据反复） |
| 系列段调课影响下游"风采点评 / 资料 / 作业"已生成内容 | 旧时间产物不删，添加"原计划于 3/14"标签；新时间下重新生成入口（教师手动触发） |

### 5.4 上下游联动（写库 + 推送）

复用现有 `EDU_IM_PRESETS.seriesReschedule* / seriesLeave* / studentLeaveRequest / parentLeaveRequest`；新增：

- `attendanceCheckInReminder({ studentName, seriesName, outlineLabel })` → 学生 / 家长（课前 5 分钟未签）
- `attendanceMakeupApprovedNotice({ ... })` → 学生 / 家长（补签通过）
- `attendanceMakeupRejectedNotice({ ..., reason })` → 学生 / 家长（补签驳回，含原因）

### 5.5 管理者（场景 9）入口

履约卡上点击 ✅/🚫/✏️ 不进单课子 CUI，而是 push `<<<RENDER_EDU_FULFILLMENT_DASHBOARD>>>` 到主 CUI：

- 「待审批 12 / 已通过 84 / 已拒绝 3」
- 「频繁请假学员 5 名 → 一键转家访话术」
- 「调课冲突 2 处 → 自动给出推荐时段方案」

## 6. 板块 ③ 作业闭环

### 6.1 业务定义

作业 = 课中"随堂练" + 课后"个性化作业" + "AI 批改" + "错题本回灌" 的端到端链路。要求：
- 老师**不重复出题**：所有作业都从 AI 备选项中"采纳 / 改 / 弃"；
- 学生**不做无效题**：作业内容与本节学情画像 + 历史错题强相关；
- 家长**不替做**：可看进度 / 可看正确率 / 可看 AI 评语，但**不**直接看到题面与答案，避免家长用搜题工具反作弊（强红线）。

### 6.2 数据模型

```
LessonHomework {
  seriesId, outlineIndex, lessonKey
  inClassQuiz[]  // 课中随堂题（教师 push 的题）
  postLessonAssignment {
    id, deadlineAt
    sourceTags: ["本节高频错点", "本章前置薄弱", "本生历史错题"]
    layeredVersions: {
      A_advanced: Question[],
      B_consolidate: Question[],
      C_remedial: Question[]
    }
    sentTo: { studentId: layer }[]
  }
  studentSubmissions[] {
    studentId
    answers[], submittedAt
    aiReview { score, perQuestion[], confidence, suspectAnomaly? }
    teacherFinal? { adjustedScore?, comment?, confirmedAt }
    redoFromMistakeBook?: boolean
  }
  parentVisibility: {
    showProgress: true,
    showQuestions: false,   // 默认家长看不到题面
    showCorrectAnswers: false
  }
}
```

### 6.3 角色 × 体验

#### 老师（场景 6）

**课中**：履约卡的「📝 作业」入口在课中阶段会高亮"AI 已根据课中表现起草今晚作业"，点入子 CUI push **`HomeworkPrepCard`**：

- 顶部：本节高频错点 3 处（来自 `tc-question` 实时回流）
- 中段：AI 起草的 3 套作业（A / B / C 难度，每套含 6-10 题）
- 底部：[✓ 三档分层派发]  [仅派发 B]  [手动调整]

**课后**：「📝 作业」入口变成 **`HomeworkBatchReviewCard`**：

- 顶栏：已批 29 / 32（AI 初批 + 你确认）；高频错点 1 处
- 列表：逐生显示得分 / AI 评语 / 异常标记（疑似抄答 / 提交时间 < 30 秒等）
- 操作：单生改分 / 群发讲解视频 / 一键发提分建议给家长 / 把高频错点导入下节备课

#### 学生（场景 7）

履约卡点「📝 作业」→ 子 CUI push **`HomeworkDoCard`**：

- 顶栏：本节作业 1 项 · 10 道 · 截止明早 8:00 · 难度 ★★☆
- 中段：题目卡（一题一卡，可往返）；遇到卡点支持"问提问帮手"（思路引导，不给答案）；
- 底部：[提交]  [先存草稿]  [转给王老师答疑]
- 提交后：1 分钟内出 AI 评分 + 逐题反馈；错题自动入"我的错题本"；"重做错题"chip 一键开始挑战。

#### 家长（场景 8）

履约卡点「📝 作业」→ 子 CUI push **`HomeworkParentViewCard`**：

- 仅展示：今晚作业有几道、已完成 0/10、用时进度条、AI 给的"今晚怎么陪练"3 条建议；
- **不**展示题面、不展示答案；
- 提供 1 个 CTA："今晚 21:00 提醒孩子做完"加入家庭日历。

> 此约束是为了避免家长直接搜题给孩子答案。允许的是"陪伴 + 鼓励 + 设定环境"，不允许"代做 / 代批"。

#### 管理者（场景 9）

不进单课子 CUI；履约卡上看：每班作业达成率（按学科 / 老师 / 班级），低达成率班级可一键"派教研复盘"。

### 6.4 AI 批改的"人工兜底"原则

- AI 自动给的分数 ≥ 90% 置信度 → 直接出分，无需教师确认；
- AI 置信度 70-90% → 进入老师"待复核"队列，教师 24h 内必看；
- AI 置信度 < 70% 或检测到抄答异常 → **强制**老师人工，AI 仅给参考；
- 学生看到的"AI 评分"始终标注"AI 初批 / 老师已复核"两态，避免学生质疑算分客观性。

### 6.5 错题本回灌

学生提交后，错题自动进入"我的错题本"（已有 chip "重做错题"承接）。错题本回灌进**下节课开场 5 分钟**，由教师在备课时一键"采用本周高频错点开场"（已有 `把.*导入下节课开场` 命中）。

### 6.6 异常与降级

| 异常 | 行为 |
|---|---|
| 学生未在截止时间前提交 | "已扣 X% 完成度，可申请延期 24h"，1 次 / 月免费；申请进入老师审批 |
| AI 批改对错题有错判 | 学生 1 键"申诉"→ 进老师人工队列 |
| 家长私自要孩子改答案后再提交 | 系统记录"提交-修改-再提交"行为标签，老师可看，但不公开给家长（防对抗） |
| 学生设备掉线 / 答案丢失 | 题目作答状态自动云端打点，1 分钟同步一次；最差掉线只丢 1 分钟内容 |
| 网络极差时全离线 | 学生可 PDF 下载本次作业（家长签字回传），AI 不批改，老师手动批 |

## 7. 板块 ④ 备课与资料

### 7.1 业务定义

复用 `eduCoursesPersistence` 已有的 "教学大纲 → AI mock 解析 → 自动建课次目录" 能力，向以下两个方向扩展：

1. **散落资料 → 自动归类到对应课次**（机构盘里散落的未归档文件，AI 按文件名 + 内容指纹判定归到哪一课次）
2. **统一查看视图**：教师有"备课视图"（含 AI 建议的扩充资源）、学生 / 家长有"资料只读视图"

### 7.2 数据模型扩展

在现有 `CourseRecord` 上新增：

```
CourseRecord {
  ...,
  unfiledFiles: WeDiskFile[]    // 已上传但 AI 未能确定归到哪一课次的"待归档"
  filingProposals: {            // AI 归档草案队列（待老师确认）
    fileId, suggestedLessonKey, confidence, reasonText
  }[]
}
```

### 7.3 大纲解析 + 自动建目录（已有）

教师在"教育微盘 → 教学资料 → 课程"内点"上传教学大纲" → 1.5s 后自动 mock 解析 → N 个"第 N 节·待补充标题"目录被建出。后续：

- 老师可手动改课次标题（命名是教师强意愿环节）；
- 老师可"AI 重建大纲"——读取现有课件文件指纹，反推 N 节并生成标题候选，老师勾选；
- 大纲版本管理：每次重建生成 v2 / v3，可比较与回滚。

### 7.4 散落资料 → 自动归类

新增"AI 一键整理"按钮（教师课程根级）：

1. 弹出 `<<<RENDER_AIC_FILING_PROPOSAL_CARD>>>` 草案卡：
   ```
   待归档 24 项 → AI 已起草归类
   · 力的合成 - 例题 v3.docx  →  第 5 节《力的合成与分解》  置信 92%
   · 弹力实验录像.mp4         →  第 2 节《重力与弹力 · 章末测》  置信 88%
   · ...
   · 杂项 3 项（AI 无法判断）   →  保留在"未归档"目录
   ```
2. 老师可"全部采用 / 取消单条 / 批量改归到 X 课次"；
3. 采用后：文件移动到对应课次目录；同步通知"已绑定该课次"的所有学员 / 家长（已发送 ≥ 1 节的课次）"该节资料已更新"（但**不**强推文件本体，避免打扰）。

#### AI 判定的输入

- 文件名关键词
- 文件元数据（创建时间 / 来源软件）
- 同名文件历史归档轨迹
- 文件内首屏文字 OCR（PDF / Doc / Slide）
- 视频 / 音频按"剪辑时间窗 ≈ 课次时间窗"参考

> 不读取文件正文细节超过首屏 200 字，避免合规争议。所有 AI 决策都以"草案 + 置信度 + 1 句理由"形式呈现，老师拥有最终决定权。

### 7.5 角色 × 资料视图

#### 老师（场景 6）— 备课视图

履约卡「📁 资料」→ 子 CUI push **`LessonMaterialsCard`（已有）+ 教师专属增强`备课视图`**：

- 下半截新增：「AI 备课助手」面板
  - 缺失 N 项（AI 检查发现：本节缺"前置题"、缺"板书底图"，给出补建议）
  - 推荐 N 项（同年级同学科其他老师**已公开**的优质素材，老师可一键导入）

- 仅展示**本节相关 + 已发送给学生的资料**（教师未发送的"备课素材"对学生不可见）；

- 异常素材审计：被学生 / 家长举报"内容不当"的素材清单

## 9. 通用性 / 合理性自检

### 9.1 自检：是否过度功能设计

| 功能 | 是否过度 | 自检结论 |
|---|---|---|
| 风采点评"伤害性表达"自动柔化 | 增加了一层措辞约束 | ✅ 必要：教育场景一旦伤害言论被发出，后果严重，AI 兜底很关键 |
| 风采报告二审制（被举报多次的老师） | 增加流程 | ✅ 必要但低频：仅触达 < 5% 老师，机构合规需要 |
| 风采点评 A/B/C 三视图按 stage + 状态自动路由 | 多一种粒度 | ✅ 必要：避免老师在过程态被"识别中..."打断；学生家长在课前进入也不会看到老师工作流细节 |
| 班级共同片段智能糊脸 | 增加生成端复杂度 | ✅ 必要：隐私强红线，且老师无法手动逐张判断 |
| 单节调课 / 系列段调课区分 | 多一种粒度 | ✅ 必要：避免学生家长一次申请影响全班 32 人 |
| AI 批改置信度三档 | 可以只做"AI 批 + 老师全审" | ✅ 必要但可后置：90% 置信直出可省老师 70% 复核时间，价值高 |
| 散落资料 AI 归档 + 草案 | 可以让老师手动建文件夹 | ✅ 必要：机构散落资料是真实痛点，AI 草案 + 老师确认是最低成本 |
| 家长不看作业题面 | 是产品红线，不是功能 | ✅ 必要：是反作弊红线，不是过度 |

### 9.2 自检：是否过度收敛

| 功能 | 是否过度收敛 | 自检结论 |
|---|---|---|
| 学生 / 家长课前/课中点风采点评看到空状态 | 不展示老师素材累积过程 | ✅ 合理：避免暴露老师工作流细节，文案明确"老师会在结束后发送" |
| 学生 / 家长看不到同班其他孩子的个人切片 | 班级共同片段也做糊脸 | ✅ 合理：哪怕授权自己孩子也不放开看别人，隐私底线 |
| 家长不看完整课堂回放 | 只看摘要 | ⚠ 可能过度：需要为愿付费家长提供"申请观看完整回放"通道（默认关，机构开通） |
| 管理者不进子 CUI | 仅看板和审批 | ✅ 合理：单课对 admin 无意义，"在哪一课"不是 admin 关心点 |
| 调课冲突的"软冲突 / 强冲突"分级 | 全部强阻断更安全 | ✅ 合理：节假日 / 家长偏好等是软信号，强阻断会让机构无法运营 |

### 9.3 自检：与现有体系是否割裂

| 现有体系 | 是否被本 PRD 改动 |
|---|---|
| 18 张 Skill 卡 | ❌ 不动；4 板块卡片与之并行，互为入口 |
| 课次抽屉 / 调课-请假 marker | ❌ 不动；本 PRD 只把"履约 11 图标"接到现有 marker，attendance 模型扩字段不拆 key |
| `eduCoursesPersistence` | ✅ 扩字段（unfiledFiles / filingProposals），不破坏现有 4 个 hook（subscribe/list/upload/delete） |
| `eduImBus` | ✅ 新增 ~ 6 个 preset（同型签名），不变更现有 12 个 |
| 顶栏教育空间切换 | ❌ 不动；新能力均落在子 CUI 内 |

### 9.4 异常态合并清单（横切）

为了不让每个板块各写一遍异常态，统一约定：

1. **AI 服务降级**：所有 AI 生成 / 批改 / 归档接口超时（风采点评 > 60s 含 2 次 retry / 其它 > 30s）→ 兜底"先手工，待会儿 AI 给草稿"，**永不**让用户卡在 loading；
2. **课时归属调整**：调课 / 请假后的产物（风采点评 / 资料 / 作业）默认沿"原课次"挂；如确实迁移，需教师手动触发，避免数据漂移；
3. **多设备同账号**：所有写操作以 last-write-wins，但被覆盖端 IM 收到"你的操作已被另一端覆盖"提示；
4. **隐私撤销实时生效**：家长撤销人脸 / 影像授权后 ≤ 5 分钟所有相关展示置灰 / 模糊；
5. **AI 中间态不阻断主流程**：风采点评未匹配素材、作业 AI 批改置信度低、资料 AI 归档不确定 ——— 一律以"折叠条 / 标签 / 提示" 形式挂在主视图边缘，不阻断老师 "一键全发 / 一键采纳" 的主路径；
6. **历史数据可逆性**：所有"撤回 / 撤销"都有 7 天回收站；超过 7 天再恢复需教务介入。

### 9.5 通用性结论

- 三类角色（teacher / student / parent）都能在**同一个系列子 CUI**完成与本节相关的全部交互，无须跳出；
- 所有 4 大板块的入口 = 履约卡上 11 个图标的子集（统一入口）；
- 所有 4 大板块的数据模型都在现有 `eduCoursesPersistence` + `aiClassroomLessonSeriesPersistence` 基础上扩字段；
- 所有 AI 输出都强制"草稿 → 人工确认 → 发布"三态，没有"AI 直发"的不可逆操作；
- 管理者（场景 9）始终只看板 / 审批，不进单课，符合"管理者不上课"的角色定位。

## 10. 验收要点（产品视角）

下述指标用于验收，技术实现与埋点方案另文展开。

### 10.1 业务指标（每月统计）

| 指标 | 目标 |
|---|---|
| 风采报告发送率 | 教师本月已上课课次中 ≥ 80% 发出过风采报告 |
| 风采点评"伤害性表达"触发率 | < 0.5%（AI 拦截后教师无视强发占比） |
| 风采报告生成 → 首发的中位时长 | 老师 ≤ 6 分钟（衡量审核效率，AI 草稿质量足够 ↑） |
| 老师对单生句的人工改写率 | < 40%（高了说明 AI 写得不像本人，需要 prompt 治理） |
| 家长打开风采报告 feed 率 | ≥ 70% |
| AI 素材归属准确率（老师未改归占比） | ≥ 85% |
| 课中签到自动达成率 | 线上 ≥ 95% / 线下 ≥ 90% |
| 请假 4h 内审批率 | ≥ 95% |
| 调课冲突拦截误报率 | < 5%（被老师标"误拦"占比） |
| 作业 24h 内 AI 批改完成率 | ≥ 90% |
| 作业批改后老师人工调整率 | < 20%（高了说明 AI 批不准；低了说明老师没复核，都需治理） |
| 大纲解析自动建目录采纳率 | ≥ 85%（老师未手动重建占比） |
| 散落资料 AI 归档采纳率 | ≥ 70%（老师不改归占比） |

### 10.2 体验指标

- 单课履约场景内"任务完成 to 关闭子 CUI"中位时长：教师 < 5 分钟、学生 < 8 分钟、家长 < 2 分钟
- 履约卡 10 入口 → 进入子 CUI 后自动定位到正确卡片的成功率 = 100%（路由正确性）
- 风采点评 A/B/C 三视图按 stage + 发布状态自动路由准确率 = 100%
- 家长侧"AI 自动 push"事件 ≤ 6 条 / 课次（避免打扰）

### 10.3 验收 Demo 路径

1. **场景 6 老师 · 风采点评全链路**：
   - 课前进入 → 视图 A 空状态 → 拍 / 传 3 张 → 退出
   - 切到 stage=in → 视图 A 累积到 12 张 → 退出
   - 切到 stage=post → 视图 A + 「✨ AI 生成」CTA 高亮 → 点击 → toast + 系统消息行 → 30s 后升级为「草稿就位 30 张」→ 进入视图 B → 改 1 条总结、改 3 条点评、未匹配素材"一键采纳为班级共同片段"→ 一键全发 → 视图升级为 C「✅ 已发 30」
2. **场景 8 家长 · 风采报告接收**：
   - 课前进入 → 空状态文案"老师会在本节结束后整理并发送"
   - 等老师发送后 →《主CUI交互》主对话收到 1 条 IM feed → 点开自动跳到本节风采报告（自家孩子视图）→ 看课堂总结 + 我家孩子的素材 + 一句点评 → 「转发到家庭群 / 👍 已读」
3. **场景 7 学生 · 签到补签**：履约卡 → ✅ → 看签到 → 申请补签 → 切到场景 6 审批
4. **场景 8 家长 · 代请假**：履约卡 → 🚫 → 代请假 → 切到场景 6 审批 → 切回场景 8 看通知 → 切回老师场景 6 看到该生被 §5.2.2 "课后 AI 生成跳过个人切片归属"
5. **场景 6 老师 · 作业**：履约卡 → 📝 → 派发分层作业 → 切到场景 7 做题 → 提交 → 切回场景 6 看 AI 批改 + 复核 → 切到场景 8 看"今晚怎么陪练"
6. **场景 6 老师 · 资料**：履约卡 → 📁 → 上传新课件 → AI 归档草案 → 采用 → 切到场景 7 看资料更新

## 11. 关键术语

| 术语 | 含义 |
|---|---|
| 系列课 | 同一份课包内 N 节课的整体（参考 `AiClassroomLessonSeries`） |
| 课次 / outline | 系列内的具体一节课（参考 `AiClassroomSeriesLessonOutline`） |
| 主线节 | `boundLessonId === DEMO_LESSON.id` 的课次，拥有 18 张完整 Skill 卡 |
| 履约卡 | 《组织状态》→ 教育 → 课程履约页签内的 `EduCourseFulfillmentCard` |
| 系列子 CUI | 进入某节课后右侧打开的对话窗口（`AiClassroomSeriesSideConversationPanel`） |
| 会上课的人 | teacher / student / parent，对应类型 `EduLessonAttendingRole` |
| 学情画像 | `tt-portrait` Skill 卡数据（高完成度 / 中等 / 需关注） |
| 家长 feed | 家长《主CUI交互》主对话内由教育系统自动 push 的 IM 卡 |
| **风采点评** | 老师侧动作向入口名（履约卡文字按钮）；对应 §4 板块 ① 的所有素材采集 + AI 转换 + 草稿审核 + 发布操作 |
| **风采素材** | 课前 / 课中 / 课后未发布的原始照片 + 视频片段（过程态），由老师在视图 A 拍 / 传 / 删 |
| **课堂总结** | AI 课后基于教学内容自动生成的本节课"教学内容 + 重难点"班级粒度产物（1 条），家长侧每张孩子的风采报告里都会带上 |
| **个性化点评** | AI 课后基于课中互动 + 学情数据为每位学员生成的**一句话**评语（学员粒度，N 条），老师可改写、可重生 |
| **课后报告 / 风采报告** | 给到单个家长的最终产物 = 该生的素材切片 + 班级课堂总结 + 该生一句话个性化点评。**老师侧**称"课后报告"（草稿态）/"已发风采报告"（终态）；**学生 / 家长侧**统称"风采报告" |

## 12. 待沟通 / 后续

1. **人脸授权链路**：本 PRD 假定"机构注册时已采集家长授权"，实际需法务确认授权范围与撤销机制；
2. **大纲 AI 解析**：当前 demo 是 1.5s mock，真实接入需明确"识别准确率达到多少才算可用"的产品门槛（建议 ≥ 85%）；
3. **作业题库来源**：本 PRD 默认 AI 出题，是否允许接入第三方题库（与机构现有付费题库整合），需运营评估；
4. **跨学科 / 跨学段适用性**：本 PRD 以"初一物理"为锚点 demo；语文（作文批改）、英语（口语评测）等学科有独立批改逻辑，下个版本以"作业批改插件化"承接；
5. **管理者审计深度**：评价 / 作业 / 资料的"被举报后处理流程"是否需要纳入审批工作流系统，需与机构售后侧对齐。
